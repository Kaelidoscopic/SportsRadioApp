# Playback-only WebRTC integration

The prototype uses `io.getstream:stream-webrtc-android:1.3.10` from Maven Central, SHA-256 `afa3b0feaa2902f6ece10e67ce3b7e6d9def18a86b73f0c6a524209cb938aa96`. This is an open-source native SDK, not a GetStream hosted service; no service account/key or paid API is used.

`preparePlaybackWebRtc` verifies this hash, rebuilds only `classes.jar` inside a generated AAR and removes `org/webrtc/audio/WebRtcAudioRecord` plus its nested classes. Native libraries and all other SDK classes stay unchanged. The app supplies its own playback-only class with that exact JNI ABI. It is compiled from source, uses the SDK's existing `nativeCacheDirectBufferAddress` / `nativeDataIsRecorded` entry points and never creates Android AudioRecord. Actual AudioRecord construction remains solely in the Stage 1 AudioPlaybackCapture adapter. No reflection, privileged Android API, native hooking or microphone fallback is used.

This is a deliberately version-specific custom Java audio-device implementation, not a stable public external-audio API. **Do not upgrade the AAR without reviewing constructor/method/native signatures and rerunning physical decoded-audio tests.** Build hash failure is intentional. Debug APK supports the SDK's bundled armeabi-v7a, arm64-v8a, x86 and x86_64 binaries; only the attached Hisense device has been exercised. Public production distribution/security review and release optimization/signing are not established by this debug prototype.

The SDK still contains other unused microphone-related classes. The application explicitly supplies our ADM to PeerConnectionFactory, never uses the default factory microphone ADM and removes/replaces the recording endpoint of the selected Java ADM. The adapter passes **every** captured frame to a bounded queue before the independent 10 Hz meter sampling. Tests must verify this full-rate path rather than feeding only displayed meter windows.

Native input consumes 480 mono PCM16 samples at 48 kHz every 10 ms. Partial native capture reads are reframed without dropping samples within a block. Queue capacity is five blocks (50 ms); oldest blocks are dropped on overflow, and underruns produce silence. Drops are expected while no listener is consuming audio. No PCM is written to disk. The counter `native input callbacks` advances only after the JNI delivery call returns; it does not alone establish audibility. Use decoded receiver RMS and ultimately a real-phone listening test.
